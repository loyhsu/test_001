# MVP 隐私与数据流转清单

本清单记录当前实现与产品规格中的数据处理方式，供备案、微信隐私保护指引和上线审核使用。上线前必须结合实际 CloudBase / Cloud Run 环境、隐私文案和数据处理协议复核；它不是法律意见。

| 数据 | 用途 | 存储位置与接收方 | 保存期限与删除方式 | 对外共享 |
|---|---|---|---|---|
| 用户主动选择的原始照片 | 图片内容安全检查、抠图和生成 | 微信客户端先做格式/大小校验；上传到 CloudBase 私有存储 `uploads/{ticketId}/{requestId}/source.*`，处理时由同一项目的生成服务通过短期临时 URL 读取；抠图完成后服务端将文件 ID 和到期时间关联到上传票据/作品 | 未完成抠图的 `issued` 票据沿用 15 分钟有效期；抠图成功后，原图从抠图完成时起 24 小时到期。票据尚未消费时，清理任务每小时扫描并删除源图、对应透明主体和票据；票据已消费时，由 Work 生命周期每小时清理文件。正常运行时到期后实际删除延迟小于 1 小时（最长接近 25 小时），任务故障或积压时可能更久。用户删除作品不会提前删除仍在有效期内、可复用的图片 | 不向广告网络或社交平台发送原图。会在同一业务链路内传给 CloudBase 内容安全和生成服务 |
| 透明主体临时图 | 在编辑器预览、生成 GIF 和 24 小时内“再做一个”时复用抠图结果 | 当前 CloudBase 私有存储 `uploads/{ticketId}/{requestId}/subject.png`；服务端只向客户端返回短期临时 URL，不返回永久文件 ID；Work 记录在票据消费时接管该文件引用 | 到期时间为抠图完成后 24 小时；未消费票据的透明图由票据清理删除，已消费票据的透明图由 Work 生命周期清理并清空 `subjectFileId`。每小时扫描，正常运行时到期后实际删除延迟小于 1 小时；故障或积压时可能更久 | 不向广告网络或社交平台发送 |
| 上传票据元数据 | 将用户、请求、源图路径和预处理结果绑定，并阻止未抠图或不属于用户的文件进入生成 | `upload_tickets` CloudBase 集合；票据消费时 Work 事务校验 owner、请求 ID、状态、源路径和透明主体，再创建 Work | 未消费的 `issued` 票据连同源图/透明图在到期后删除；消费后立即清空票据上的用户、请求和文件引用，只保留 `workId`/消费时间，图片由 Work 生命周期管理；源图与透明主体到期清理时一并删除 consumed 票据 | 仅由本项目服务端使用 |
| GIF 成品、封面 | 作品预览、相册保存、分享卡片 | 当前 CloudBase 私有存储 `works/{workId}/result.gif`、`cover.jpg`；相册保存由用户主动触发 | 到期时间为生成后 30 天；每小时清理任务到期后删除文件、将作品标记为 `expired` 并保留作品数据库记录，正常运行时实际删除延迟小于 1 小时；故障或积压时可能更久。用户主动删除作品时删除成品和封面 | 不自动发布。分享卡片会携带作品 ID 和短期封面 URL；当前跨账号打开链路尚未验收，见发布检查表 |
| 微信 `openid`、作品元数据与编辑状态 | 作品归属校验、历史列表、删除权限、生成恢复 | `works` CloudBase 集合；服务端从可信微信上下文取得 `openid`，客户端不提供身份 | 普通过期作品记录保留至用户删除；用户删除时立即隐藏作品、删除 GIF/封面并清除记录中的 `openid`、模板和编辑状态，仅保留源图/透明图到期清理所需的最小 tombstone；24 小时文件清理完成后同时删除 tombstone 和 consumed 票据。定时任务故障或积压时可能延迟 | 仅用于本服务的身份与作品管理；生成服务不需要 `openid` |
| 产品行为事件 | 评估模板浏览、生成成功率和保存等功能使用情况 | 客户端仅发送 11 个固定事件及白名单属性；CloudBase 服务端附加 `SHA-256(openid)` 写入 `analytics_events`。这是可关联的假名化标识，不应宣传为匿名数据 | 产品规格未规定埋点保留期，当前未配置 TTL 或清理；上线前须确定最长期限与删除规则 | 不发送给广告网络。可在本项目 CloudBase 管理权限范围内查看 |
| 相册 | 用户选择一张图片或将成品保存到设备 | 微信系统选择器和用户设备；只通过选择器选取单张照片，不读取相册列表 | 选择器返回的临时本地路径按系统机制处理；不作为长期云端存储 | 仅用户主动选择/保存时与系统相册交互 |

## 必须在上线前确认

- 为 `analytics_events` 设定可执行的保留期限和删除策略；当前没有 TTL。
- 明确 30 天后保留 `works` 记录多久；定时任务按设计保留并标记过期，数据库记录不会自动消失。
- 在隐私指引明确“到期后由每小时清理任务删除，正常情况下可能延迟不到 1 小时”；故障时延迟无硬性上限，需监控与补偿。如必须严格保证 24 小时内物理删除，应采用按到期记录触发/查询并验证故障补偿，不能只依赖定时扫描。
- 当前每小时任务会分页读取全部作品记录；记录量增长时需压测读取成本与执行时长，必要时加到期字段索引与补偿队列。
- 核对用户主动删除作品、分享卡片和隐私指引中的保存说明一致；本清单不得代替法务/平台审核。
- 分享卡片当前使用 owner-scoped `getWork`。需要先设计并验证安全的跨账号查看授权，不能为了让链接可用而公开原图、永久文件地址或绕过所有权校验。
- 配置并验证 CloudBase 存储读写权限为私有；对内容安全和生成服务使用最小必要的临时访问能力。
